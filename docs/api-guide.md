# API 지침

우리 API 가 지키는 규칙을 모아 둔다. 새 경로를 낼 때 여기부터 읽는다.

**이 문서는 자란다.** 새로 정할 일이 생기면 정한 뒤 여기에 적는다. 그래야 다음에
같은 것을 다시 정하지 않는다. 각 항목에는 **무엇을 정했는지**와 **왜**를 함께
적는다 — 왜가 없으면 나중에 바꿔도 되는 규칙인지 알 수 없다.

범위 결정(무엇을 만들 것인가)은 `docs/superpowers/specs/2026-09-14-scope-decisions.md`
에 있다. 이 문서는 그것을 **어떻게 드러낼 것인가**만 다룬다.

---

## 1. 스펙이 유일한 원본

`api/openapi.yaml` 을 손으로 쓰고, 거기서 서버 모델과 화면 타입을 생성한다.
생성물은 손으로 고치지 않는다.

```bash
./scripts/generate-from-spec.sh
```

**왜.** 스펙이 둘이면 어느 쪽도 스펙이 아니다. 서버가 응답을 바꿨는데 화면 타입이
그대로면, 화면은 빌드에 통과하고 실행에서 죽는다.

**지킬 것.** 스크립트를 돌린 뒤 `git status` 가 깨끗해야 한다. 차이가 나면 누군가
생성물을 손으로 고친 것이다.

## 2. 주소

### 자원을 가리킨다

```
GET   /api/v1/public/members                클랜원 목록
GET   /api/v1/public/members/{memberId}     클랜원 한 명
PATCH /api/v1/admin/members/{memberId}      그 한 명을 고친다
```

주소는 **무엇**을 가리키고, 무엇을 할지는 메서드가 말한다.

### 버전을 단다

모든 경로에 `/api/v1/` 을 단다. 부르는 쪽이 우리 화면 하나뿐이어도 그렇게 한다.

**왜.** 브라우저는 옛 자바스크립트를 캐시에 들고 있다. 배포된 화면은 그것을
갈아 치운 배포보다 오래 산다. 이 저장소는 캐시된 `style.css` 에 한 번 물린 적이
있다.

### 우리 식별자와 바깥 식별자를 가른다

```json
{ "id": "957e42fd-...", "externalId": "#R2LLCUUL" }
```

`id` 는 우리가 만든 UUID 이고 `externalId` 는 CoC 태그다. **주소에는 `id` 를
쓴다.** CoC 태그에는 `#` 이 들어 있어 주소에서 조각 구분자로 읽히기 때문이다.

바깥 식별자로 찾아야 하면 쿼리로 좁힌다.

```
GET /api/v1/public/members?externalId=%23R2LLCUUL
```

## 3. CRUD 가 아닌 동작은 콜론으로 붙인다

```
POST /api/v1/members:sync     클랜 명단을 지금 맞춘다
POST /api/v1/wars:sync        클랜전 기록을 지금 받아 온다
```

**왜.** 만들고·읽고·고치고·지우는 넷에 안 맞는 동작이 있다. 세 갈래를 견주었다.

| 안 | 무엇이라고 말하는가 | 판정 |
|---|---|---|
| `POST /syncs` | "동기화 실행이라는 자원을 만든다" | 실행을 기록으로 남기고 `GET /syncs/{id}` 로 읽을 수 있을 때만 참이다. 그러지 않으면 명사 옷을 입은 동사다 |
| `POST /members/sync` | "members 아래 sync 라는 자원" | `sync` 는 자원이 아니다. 동사를 경로 조각에 숨겼다 |
| **`POST /members:sync`** | "members 에 sync 라는 동작을 건다" | **표준 메서드가 아님을 드러낸다. 숨기지 않는다** |

콜론 방식은 구글 API 설계 지침(AIP-136)이 쓰는 것이고, RFC 3986 이 경로 조각에
`:` 를 허용한다.

**언제 이것을 쓰나.** 넷에 억지로 맞추면 거짓말이 될 때만. 억지로 맞추는 것보다
드러내는 편이 낫다는 판단이며, 자주 쓰면 API 가 원격 호출 묶음이 된다.

**언제 자원으로 올리나.** 그 실행을 나중에 다시 읽어야 하면 그때 자원으로 만든다.
기록이 필요해진 순간이 그 신호다.

## 4. 응답은 덩어리로 나누고 부르는 쪽이 고른다

```
GET /api/v1/public/members                          우리 값만. DB 한 행 읽기
GET /api/v1/public/members?include=profile          + CoC 현황. CoC 호출
GET /api/v1/public/members?include=profile,league   + 이번 달 점수·순위·등급
```

기본 응답은 **가장 싼 것**만 담는다. 비싼 것은 청할 때만 싣는다.

### 매개변수 이름은 단수 `include`

값이 여럿이어도 단수다. 쉼표로 잇는다.

**왜.** `include` 는 동사다 — "포함시켜라"는 명령이다. `includes` 는 3인칭 단수
현재형이라 "포함한다"는 서술이 되어 시키는 말이 아니게 된다. `sort`·`filter` 를
복수로 쓰지 않는 것과 같다. JSON:API 가 명세로 정한 이름이기도 하다.

명사로 이름 붙이는 매개변수는 복수가 맞다(`fields`, `labels`, `ids`). 갈림길은
개수가 아니라 품사다.

### 어휘는 정해 둔다

| 이름 | 무엇 |
|---|---|
| `profile` | CoC 가 주인인 값 — 이름·직책·홀·트로피·기부 |
| `league` | 리그전 선발 — 이번 달 점수·순위·등급 |

늘리려면 이 표를 먼저 고친다. 모르는 이름이 오면 **400 으로 거절한다** — 조용히
버리면 부르는 쪽은 덩어리가 빠진 것을 오타 때문인지 값이 없어서인지 모른다.

### 부르지 않은 덩어리는 키 자체가 없다

```json
GET /api/v1/public/members
{ "id": "...", "externalId": "#R2LL..." }              profile 키가 없다

GET /api/v1/public/members?include=profile
{ "id": "...", "profile": { "name": "히로", ... } }     실려 온다

GET /api/v1/public/members/{id}?include=profile
{ "id": "...", "profile": null }                        물었지만 CoC 에 없다
```

`null` 로 채우지 않는다. **묻지 않은 것과 값이 없는 것은 다르다.**

FastAPI 에서는 경로에 `response_model_exclude_unset=True` 를 주고, 고르지 않은
덩어리를 모델에 아예 넘기지 않는 것으로 얻는다.

## 5. 응답은 사실만 담는다

```json
{ "role": "ADMIN" }        ○
{ "role": "장로" }          ✕
```

표시 문자열을 응답에 넣지 않는다.

**왜.** 넣는 순간 다국어가 서버 일이 되고, 문구 한 줄 고치는 데 서버 배포가
필요해진다. 무엇으로 보여줄지는 화면이 정한다.

같은 이유로 **대신할 값을 서버가 고르지 않는다.** `displayName` 이 비면 비운 채로
내보내고, 화면이 `displayName ?? profile.name ?? externalId` 로 정한다.

## 6. 부분 수정 — 보낸 것만 바뀐다

```json
PATCH /api/v1/admin/members/{memberId}
{ "warnings": 2 }
```

| 요청에 | 뜻 |
|---|---|
| 필드가 없다 | 그대로 둔다 |
| 필드가 `null` | 비운다 |
| 필드에 값 | 그 값으로 바꾼다 |

**왜.** 앞의 둘을 가르지 않으면 경고만 올리려는 요청이 관리자 메모를 함께 지운다.

Pydantic 에서는 `model_fields_set` 이 실제로 실려 온 키를 알려 주므로 그것으로
가른다. 도메인에는 "안 보냈다"를 나타내는 표시(`UNSET`)를 따로 둔다 — `None` 은
"비워 달라"는 뜻으로 이미 쓰이고 있기 때문이다.

**하나도 안 보내면 400.** 고칠 것이 없는 요청은 받아도 할 일이 없는데 갱신 시각만
올라간다.

**비울 수 없는 값에 `null` 이 오면 400.** 생성 모델은 선택 사항인 필드를 모두
`| None` 으로 적으므로 스펙이 막아 주지 못한다.

## 7. 오류

```json
{ "detail": "그 클랜원이 없습니다" }
```

FastAPI 의 `HTTPException` 이 내는 모양과 같게 둔다. 스펙에 `Error` 로 적혀 있다.

| 코드 | 언제 |
|---|---|
| 400 | 본문이나 매개변수가 우리 규칙에 안 맞는다. 모르는 `include`, 빈 `PATCH` |
| 404 | 그 식별자를 가진 것이 없다 |
| 422 | 스펙이 정한 형식에 안 맞는다. 생성 모델이 먼저 거른다 |
| 503 | 우리가 기댄 바깥(CoC, 자격 증명)이 없다 |

**500 을 그대로 내보내지 않는다.** 500 은 "우리 잘못인데 무엇인지 모른다"는 뜻이라
원인을 가린다. CoC 자격 증명이 없어 현황을 못 주는 것은 503 이고, 그 사실을
`detail` 에 적는다.

## 8. 이름과 형식

| | 규칙 |
|---|---|
| 응답 필드 | 캐멀케이스 (`donationsReceived`) |
| DB 열 | 스네이크케이스 (`donations_received`) |
| 바꾸는 자리 | 경로의 `_to_schema` 한 곳 |
| 시각 | ISO 8601 UTC 문자열 (`2026-09-15T01:47:28Z`) |
| 열거형 | 대문자 (`ADMIN`, `ACTIVE`) |

### `format: uuid` 와 `format: date-time` 을 쓰지 않는다

**왜.** 생성기가 `UUID`·`AwareDatetime` 타입을 만드는데 우리 도메인은 둘 다
문자열로 다룬다. 그러면 경로가 생성 모델을 못 쓰고 응답 사전을 손으로 만들게
되고, 스펙을 고쳐도 그 사전은 따라오지 않는다. 실제로 한 번 겪었다.

무엇인지는 `description` 에 적는다.

### `nullable` 은 `required` 에서 빼는 것으로 적는다

이 저장소의 관례다. `required` 에 있으면서 `nullable: true` 인 필드는 생성기가
`| None` 으로 만들지 않는다.

### 열거형은 세 곳이 같아야 한다

| 어디 | 무엇 |
|---|---|
| SQL | `CHECK (status IN ('ACTIVE','INACTIVE'))` |
| 스펙 | `enum: [ACTIVE, INACTIVE]` |
| 도메인 | `class MemberStatus(StrEnum)` |

한쪽만 늘리면 저장은 되는데 읽다가 죽거나, 저장이 거부된다. `test_enum_constraint.py`
가 이 셋을 견준다.

## 9. 없는 것을 미리 적지 않는다

`league` 는 어휘로 정해져 있지만 **스펙의 열거형에는 아직 없다.** 그달 점수가
있어야 나오는데 클랜전 기록이 아직 안 들어왔기 때문이다.

**왜.** 스펙에 적힌 것은 약속이다. 없는 것을 적어 두면 부르는 쪽이 있다고 믿는다.
정해진 어휘는 설명글과 결정 문서에 남기고, 실제로 답할 수 있게 되면 그때 열거형에
더한다.

## 10. 서버는 능력을 열고, 화면이 고른다

API 가 클랜 목록을 주는데 화면이 하나만 보여 준다면, 그것은 화면의 선택이지 API 의
구멍이 아니다.

오늘 화면이 덜 쓴다고 서버 경로를 좁히지 않는다. **좁혔다가 넓히려면 마이그레이션이
들고, 넓힌 뒤에 화면이 따라오려면 배포를 기다려야 한다.**

## 11. 경로를 표면으로 가른다

```
/api/v1/public/    클랜원 누구나 부른다. 로그인하지 않은 사람도
/api/v1/admin/     운영진만 부른다
```

| | 어디에 |
|---|---|
| `GET /api/v1/public/members` | 공개 |
| `GET /api/v1/public/members/{memberId}` | 공개 |
| `PATCH /api/v1/admin/members/{memberId}` | 운영 |
| `POST /api/v1/admin/members:sync` | 운영 |

**양쪽 다 이름을 붙인다.** 접두사 없는 쪽을 기본으로 두면, 분류를 잊은 경로가
조용히 공개 표면에 놓인다. 둘 다 이름이 있으면 **안 붙인 경로는 아예 안 걸리므로
잊을 수 없다.**

`public` 이지 `user` 가 아니다. 곧 `users` 자원이 생기는데
(`/api/v1/admin/users`) 한 글자 차이로 뜻이 전혀 달라 읽는 사람이 헷갈린다.
그리고 이 표면은 로그인 안 한 사람도 부르므로 "user" 보다 "public" 이 맞다.

**왜 가르나.** 표면 전체에 검사를 한 번에 걸 수 있다.

```python
app.include_router(admin_router, dependencies=[Depends(require_admin)])
```

경로마다 검사를 붙이면 **하나 빠뜨려도 조용하다.** 일괄로 걸면 빠뜨릴 수 없다.
그것이 가르는 유일한 값어치다.

**경로가 막아 주는 것은 아니다.** 주소에 `admin` 이 적혀 있다고 서버가 막지
않는다. 아무나 `POST /api/v1/admin/members:sync` 를 부를 수 있고, 막는 것은
여전히 서버의 검사다. 경로는 그 검사를 **한곳에 모으는 자리**일 뿐이다.

**치르는 값.** 한 자원에 주소가 둘이 된다. `GET /public/members/{id}` 와
`PATCH /admin/members/{id}` 가 같은 사람을 가리킨다. 자원을 가리키는 주소가
하나여야 한다는 원칙을 여기서는 포기한다 — 검사를 빠뜨리지 않는 쪽을 택했다.

**접두사는 라우터에 적지 않는다.** `worker.py` 가 한 자리에서 끼운다. 경로
파일마다 접두사를 적으면 표면이 코드 여기저기에 흩어지고, 검사를 걸 자리도
함께 흩어진다.

```python
public_router = APIRouter(prefix="/api/v1/public")
public_router.include_router(member_router)

admin_router = APIRouter(prefix="/api/v1/admin")
admin_router.include_router(member_admin_router)
```

**무엇이 어디로 가나.** 읽기는 대개 공개, 고치기는 대개 운영이다. 다만
메서드로 가르지 않는다. 클랜원이 제 메모를 고치는 일이 생기면 그것은 `PATCH`
지만 공개 표면이다. **누가 부르는가로 가른다.**

## 12. 운영 표면은 비밀번호로 막는다 (임시)

```
POST /api/v1/admin/members:sync
X-Admin-Password: <Worker 비밀값과 같은 값>
```

**임시 조치다.** 제대로 된 로그인은 나중에 온다. 그때까지 운영 표면을 열어 둘 수
없어 비밀번호 하나로 막아 둔다. 약한 곳을 알고 쓴다.

- 한 벌을 모두가 나눠 쓴다. 누가 무엇을 했는지 알 수 없다
- 새어 나가도 만료도 회수도 없다
- 요청마다 다시 보내야 하므로 화면이 그것을 들고 있어야 한다

**비밀값이 없으면 모두 막는다.** 열어 두는 쪽으로 기울면 설정을 빠뜨린 배포가
조용히 운영 표면을 공개해 버린다. 막아 두면 곧바로 드러난다.

**비밀번호는 ASCII 여야 한다.** HTTP 헤더가 ASCII 만 담는다. 한글로 정하면
브라우저가 요청을 보내지도 못하고, 서버가 거부하는 것이 아니라 아예 나가지 않아
쓰는 사람은 무엇이 잘못됐는지 알 길이 없다. 화면과 테스트가 둘 다 이것을 막는다.

**견줄 때 한 글자씩 보지 않는다.** `hmac.compare_digest` 를 쓴다. 한 글자씩
견주면 걸린 시간으로 앞자리를 알아낼 수 있다.

**검사는 한 자리에만 있다.** `worker.py` 가 운영 라우터를 끼울 때 단다. 로그인이
오면 `auth.py` 만 갈아 끼우면 되고 그 줄은 그대로다.

```python
admin_router = APIRouter(prefix="/api/v1/admin", dependencies=[Depends(require_admin)])
```

## 새 규칙을 더할 때

1. 무엇을 정했는지 한 줄로 적는다
2. **왜** 그렇게 정했는지 적는다. 견준 다른 안이 있으면 그것도 적는다
3. 되돌리려면 무엇을 치르는지 적는다
